--------------------------------------------------------------------------------
THE CORE IDEA FOR THE HACKATHON
--------------------------------------------------------------------------------
RealChain currently has a UX problem: investors hold USDC (from buying tokens
or earning rent) but STILL need ETH sitting in their wallet just to call
claimAll(), buyFromOwner(), or depositRental(). This is the exact friction
UGF solves.

Hackathon pitch:
  "Investors earn USDC rental income from property tokens. They should be able
   to claim it, buy tokens, and trade — all using only USDC. With UGF, they
   pay gas in the same USDC they earn. They never need to think about ETH."

The demo flow for judges:
  1. User has USDC. Has ZERO ETH.
  2. User clicks "Claim Dividends"
  3. UGF pays ETH gas behind the scenes
  4. UGF deducts small USDC fee from user
  5. Transaction succeeds. User never saw ETH.

WHAT NEEDS TO BE BUILT — UGF INTEGRATION
--------------------------------------------------------------------------------

This is the main new work. UGF replaces MetaMask's direct transaction signing
with a relay flow: instead of user signing and paying gas in ETH, UGF quotes
the gas, user approves USDC payment, UGF executes.

Install UGF React SDK:
  cd frontend
  npm install @tychilabs/react-ugf

The UGF integration needs to wrap these specific transactions:
  - claimAll() in Dividends.jsx         ← MOST IMPORTANT (the demo centerpiece)
  - buyFromOwner() in Property.jsx      ← SECOND PRIORITY
  - depositRental() in Dividends.jsx    ← THIRD PRIORITY
  - buyFromListing() in Property.jsx    ← FOURTH PRIORITY

You do NOT need to wrap every transaction for the hackathon demo.
claimAll() alone is enough to win the "reward claim" track.

How UGF flow works in code (conceptual — check actual SDK docs):
  OLD (current):
    const tx = await rental.claimAll();
    await tx.wait();

  NEW (with UGF):
    // 1. Get a quote from UGF for this transaction
    // 2. Show user: "This will cost $0.05 in Mock USD"
    // 3. User approves
    // 4. UGF SDK executes the transaction
    // 5. UGF deducts USDC from user
    // 6. Transaction confirmed on-chain
    (See UGF SDK docs for exact API: universalgasframework.com/docs)

Files to modify for UGF:
  frontend/src/context/Web3Context.jsx
    - Import UGF SDK
    - Add UGF client/provider initialization
    - Expose ugfExecute() or similar function to components

  frontend/src/pages/Dividends.jsx
    - Replace direct claimAll() call with UGF-wrapped version
    - Show "Gas paid in USDC" indicator to user
    - Show estimated USDC gas cost before user confirms

  frontend/src/pages/Property.jsx
    - Replace buyFromOwner() call with UGF-wrapped version (second priority)

WHAT NEEDS TO BE BUILT — ROLE-SPECIFIC PAGES (FRONTEND REDESIGN)
--------------------------------------------------------------------------------

CURRENT PROBLEM:
The frontend currently shows the same pages to everyone. Owner and investor
see the same Property page and the same Dividends page. This is confusing:
  - Owner sees a "Buy tokens" form that's irrelevant to them
  - Investor sees a "Deposit Rental Income" form that they can't use
  - There's no clear separation of what each role does

WHAT NEEDS TO BE BUILT:

The roleHint from Web3Context already detects "Owner" vs "Investor".
Use it to show different content.

OPTION A — Conditional rendering (easier, less code):
  Keep existing page structure but show/hide sections based on role.
  In Property.jsx:
    if (roleHint === "Owner") show DepositRentalSection
    if (roleHint === "Investor") show BuyTokensSection
  In Dividends.jsx:
    if (roleHint === "Owner") show DepositForm prominently at top
    if (roleHint === "Investor") show ClaimAll button prominently

OPTION B — Separate pages (cleaner, better UX, more work):
  Create new files:
    frontend/src/pages/OwnerDashboard.jsx  — owner-specific view
    frontend/src/pages/InvestorDashboard.jsx — investor-specific view
  Update App.jsx routing:
    /dashboard → shows OwnerDashboard if roleHint==="Owner" else InvestorDashboard

RECOMMENDATION: Option B for the hackathon. Judges should immediately see
a role-specific dashboard when they connect a wallet. It looks more polished.

OWNER DASHBOARD should show:
  - Properties they own (list from factory filtered by owner address)
  - For each property: token supply remaining, total rent deposited
  - "Deposit Rental Income" form with UGF gasless toggle
  - Recent epoch history
  - "Create New Property" button (calls factory.createProperty)

INVESTOR DASHBOARD should show:
  - Properties where they hold tokens (current portfolio)
  - Total pending dividends across all properties
  - "Claim All Dividends" button (UGF-powered — the hackathon centerpiece)
  - Secondary market listings they've created
  - Link to browse all properties (Home page)

NEW NAVBAR LOGIC:
  - Not connected: show "Connect Wallet" button, neutral nav
  - Connected as Owner: show "Dashboard" linking to OwnerDashboard
  - Connected as Investor: show "Dashboard" linking to InvestorDashboard

Replace with cleaner role-based navigation.

--------------------------------------------------------------------------------
WHAT THE DEMO SHOULD SHOW (FOR JUDGES)
--------------------------------------------------------------------------------

1. Open the app. Show MetaMask with 0 ETH, some Mock USD only.
2. Connect wallet. It detects "Investor" role automatically.
3. Show InvestorDashboard: pending dividends = some USDC amount.
4. Click "Claim All Dividends".
5. A popup shows: "Gas cost: $0.04 Mock USD" — NO ETH REQUIRED.
6. Confirm. Transaction goes through via UGF relay.
7. Mock USD balance decreases by $0.04 (gas fee deducted by UGF).
8. Dividend USDC lands in wallet.
9. The user never touched ETH. Never needed ETH. Never saw ETH.

This is the entire hackathon story in 60 seconds.
